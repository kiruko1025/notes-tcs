# Lecture 2: Programs, Functions, and Lambda Terms

**Core idea:** computation using only variables, functions, and application.

## Syntax and semantics

Syntax tells us which expressions belong to a language and how their pieces fit together. Semantics assigns meaning to those expressions. A program can be syntactically valid while failing a typing rule or never finishing its execution.

| Concept | Meaning |
| --- | --- |
| Syntax | Program structure; legal expressions. |
| Operational semantics | Execution steps or evaluation rules. |
| Denotational semantics | Meaning as a mathematical object. |
| Axiomatic semantics | Properties before/after execution. |
| Static semantics | Scope, typing, other pre-execution checks. |
| Dynamic semantics | Runtime behavior. |

For `x := x + 1`: syntax identifies an assignment; operational semantics explains its execution; an axiomatic statement says “if $x=4$ before, then $x=5$ after.” Different views of the same program.

## Functions

- **Relation:** $R\subseteq A\times B$.
- **Total function:** exactly one output per input.

$$
f:A\to B
\qquad
\forall a\in A,\;\exists!b\in B.\;(a,b)\in f.
$$

Read $\forall$ as “for every,” $\exists!$ as “there exists exactly one,” and $A\times B$ as pairs with first component in $A$, second in $B$.

- **Partial function** $f:A\rightharpoonup B$: at most one output; possibly undefined.
- **Graph / extension:** $\{(a,f(a))\mid a\in\operatorname{dom}(f)\}$; domain = inputs where $f$ is defined.
- **Extensional view:** input-output behavior.
- **Intensional view:** expression or algorithm computing it.
- Example: $n+n$ and $2n$ — different descriptions, same integer function.
- Programs may diverge; their computed functions need not be total.

For example, a program that returns $n+1$ for positive inputs but loops on input $0$ computes a partial function on $\mathbb N$. “Undefined at $0$” means there is no returned result there. It does not mean the function can choose several different outputs.

## Lambda syntax

Countably infinite variable set $\mathrm{Var}$; finite terms:

$$
e::=x\mid\lambda x.e\mid e_1\,e_2.
$$

| Form | Meaning |
| --- | --- |
| $x$ | Variable reference. |
| $\lambda x.e$ | Function: parameter $x$, body $e$. |
| $e_1\,e_2$ | Apply $e_1$ to $e_2$. |

- $e,e_1,e_2$: metavariables ranging over terms.
- Untyped: no restrictions on application; $x\,x$ allowed.
- Numbers/booleans: later encodings, not primitive syntax.

Read $::=$ as “can be” and $\mid$ as “or.” Every term is built from these three forms. The dot separates a function's parameter from its body; application by juxtaposition means a function call, not multiplication.

A lambda term can itself be a function or an argument to another function. For instance, $(\lambda x.x)\,(\lambda y.y)$ applies identity to a function, returning that function. The letters $e_1,e_2$ describe arbitrary terms in our explanation; they are not extra constructs in the language.

### Parsing

$$
\begin{aligned}
e_1\,e_2\,e_3&=(e_1\,e_2)\,e_3
&&\text{application: left-associative},\\
\lambda x.e_1\,e_2&=\lambda x.(e_1\,e_2)
&&\text{body extends right},\\
\lambda x\,y.e&=\lambda x.\lambda y.e
&&\text{currying}.
\end{aligned}
$$

**Watch:** $\lambda x.x\,y\ne(\lambda x.x)\,y$.

**Currying:** a two-argument function takes one argument and returns a function waiting for the second. Example:

$$
(\lambda x.\lambda y.x)\,a\,b
\to_\beta(\lambda y.a)\,b\to_\beta a
\qquad(y\notin\mathrm{FV}(a)).
$$

The side condition avoids capture; rename the binder first when needed. The reduction rule is explained below.

### Common terms

| Name | Term |
| --- | --- |
| Identity $I$ | $\lambda x.x$ |
| First selector $K$ | $\lambda x.\lambda y.x$ |
| Second selector | $\lambda x.\lambda y.y$ |
| Application | $\lambda f.\lambda x.f\,x$ |
| Composition: $f$, then $g$ | $\lambda f.\lambda g.\lambda x.g\,(f\,x)$ |

## Binding and free variables

- **Binder:** $x$ in $\lambda x.e$.
- **Bound occurrence:** refers to nearest enclosing binder of the same name.
- **Free occurrence:** no enclosing matching binder.
- **Shadowing:** in $\lambda x.\lambda x.x$, the final $x$ refers to the inner binder.

Binding is a property of each occurrence, not of a letter everywhere in the program. In $x\,(\lambda x.x)$, the leftmost $x$ is free and the rightmost $x$ is bound. The inner binder's **scope** is only its body.

$$
\begin{aligned}
\mathrm{FV}(x)&=\{x\},\\
\mathrm{FV}(e_1\,e_2)&=\mathrm{FV}(e_1)\cup\mathrm{FV}(e_2),\\
\mathrm{FV}(\lambda x.e)&=\mathrm{FV}(e)\setminus\{x\}.
\end{aligned}
$$

- **Closed term / combinator:** $\mathrm{FV}(e)=\varnothing$.
- **Open term:** at least one free variable.
- Example: $\mathrm{FV}(\lambda x.x\,y)=\{y\}$.

Free variables are the term's dependencies on its surroundings. Here the function supplies $x$, but still needs an external meaning for $y$. The abstraction rule removes $x$ from the body's free-variable set because the binder now supplies it.

## Beta reduction

$$
(\lambda x.e)\,s\to_\beta e[x\mapsto s].
$$

Replace free occurrences of $x$ by $s$; **avoid capture**.

The application $(\lambda x.e)\,s$ is a **redex**, a place where computation can happen. Its result is the body $e$ with the argument inserted at the parameter's free occurrences. This rewrites an expression; it does not change a global variable named $x$.

$$
(\lambda x.\lambda y.y)\,a\,b
\to_\beta(\lambda y.y)\,b
\to_\beta b.
$$

Capture example — rename the inner binder first:

$$
(\lambda x.\lambda z.x)\,z
\equiv_\alpha(\lambda x.\lambda a.x)\,z
\to_\beta\lambda a.z.
$$

- Correct: $\lambda a.z$, returning the original free $z$.
- Incorrect: $\lambda z.z$, which captures $z$ and becomes identity.
- $\equiv_\alpha$: same binding structure, different bound names. Details in [Lecture 3](3.md).

## Nameless representations

Bound names are useful for people, but require careful renaming during substitution. A nameless representation records which binder an occurrence refers to directly. Renaming a bound variable then leaves the representation unchanged.

Example: $\lambda f.\lambda x.\lambda y.(f\,x)\,(f\,y)$.

| Representation | Numbering | Result |
| --- | --- | --- |
| De Bruijn indices | Nearest binder = $0$; count outward. | $\lambda.\lambda.\lambda.(2\;1)\,(2\;0)$ |
| De Bruijn levels | Outermost binder = $0$; count inward. | $\lambda.\lambda.\lambda.(0\;1)\,(0\;2)$ |

In the example's body, pass $y$, then $x$, then $f$: their indices are $0,1,2$. Levels instead number those binders once from the outside: $f=0,x=1,y=2$.

At binder depth $d$:

$$
\text{index}=d-1-\text{level}.
$$

- Numbers here: binder references, not Church numerals.
- Alpha-equivalent closed terms: identical nameless representation.
- Open terms: require an external context or separate free names.
- Moving terms across binders: may require index shifting.
