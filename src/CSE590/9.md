# Lecture 9: Small-Step and Big-Step Equivalence

**Goal:** same termination behavior and final state.

$$
\boxed{
\langle c,\sigma\rangle\Downarrow\tau
\iff
\langle c,\sigma\rangle\to^*\langle\mathsf{skip},\tau\rangle.
}
$$

| Direction | Main tools |
| --- | --- |
| Big-step → small-step run | Rule induction, lifting, transitivity |
| Small-step run → big-step | Inversion, anti-reduction, induction on run |

Rules: [small-step](7.md), [big-step](8.md). Only finite runs to skip appear in the theorem; divergent runs have no finite big-step derivation.

The symbol $\iff$ requires two proofs. Forward: turn a complete evaluation tree into an execution trace. Reverse: turn a terminating trace into a complete evaluation tree. Showing just one direction would leave open whether the other semantics admits additional terminating behaviors.

## Proof tools

**Rule induction:** one case per final rule; induction hypotheses (IHs) for premise derivations. A while premise repeats the loop syntax but has a smaller proof tree.

Induction on command syntax alone cannot justify that loop case: the repeated loop is not a smaller command. Induction on its finite derivation supplies exactly the hypothesis needed.

**Expression correspondence:** prove arithmetic first, then Booleans, then commands.

$$
\begin{aligned}
\langle a,\sigma\rangle\Downarrow_a n
&\iff\langle a,\sigma\rangle\to_a^*n,\\
\langle b,\sigma\rangle\Downarrow_b q
&\iff\langle b,\sigma\rangle\to_b^*q.
\end{aligned}
$$

Expression chains below keep $\sigma$ fixed. Command IHs do not replace these separate expression lemmas.

The dependency order follows the language's syntax: comparisons contain arithmetic expressions, and commands contain arithmetic expressions and Boolean guards. Proving these smaller results first lets the command proof use them without circular reasoning.

**Closure:** zero or more steps; configurations include both command and state.

$$
\frac{}{C\to^*C},
\qquad
\frac{C\to C'\qquad C'\to^*C''}{C\to^*C''}.
$$

Consequences: one step gives a multi-step run; matching runs concatenate. Transitivity proof: induction on the first run.

In the zero-step case, concatenation simply keeps the second run. In the step case, retain the first step, use the IH to concatenate the remaining first run with the second run, then reattach that step. The same pattern proves lifting, replacing concatenation with the relevant context rule.

**Lifting:** a subrun becomes a run in its evaluation position.

$$
\langle a_1,\sigma\rangle\to_a^*a_1'
\Longrightarrow
\langle a_1+a_2,\sigma\rangle\to_a^*a_1'+a_2.
$$

$$
\langle c_1,\sigma\rangle\to^*\langle c_1',\rho\rangle
\Longrightarrow
\langle c_1;c_2,\sigma\rangle\to^*\langle c_1';c_2,\rho\rangle.
$$

Likewise for assignment expressions and guards. Right-operand lifting requires a numeral on the left. Proof: induction on subrun; lift each step with its context rule.

Lifting applies only where evaluation is currently allowed. For a sequence, steps inside $c_1$ lift through $c_1;c_2$; steps inside $c_2$ must wait until $c_1$ finishes.

## Forward: big-step → small-step run

Induct on the **big-step derivation**; join runs from IHs.

Each IH already gives a complete small-step run for one premise. The work in a case is to place those runs in the correct evaluation positions and add the administrative steps, such as selecting a branch or removing skip. Transitivity then joins the pieces.

### Arithmetic and assignment

Given operand results $n_1,n_2$:

$$
a_1+a_2\to_a^*n_1+a_2\to_a^*n_1+n_2\to_a n_3,
\qquad n_3=n_1+n_2.
$$

Last arrow: actual computation, from expression to numeral. Literals: zero steps. Variables: one lookup. Other operators: same pattern.

Given $\langle a,\sigma\rangle\Downarrow_a n$:

$$
\langle x:=a,\sigma\rangle
\to^*\langle x:=n,\sigma\rangle
\to\langle\mathsf{skip},\sigma[x\mapsto n]\rangle.
$$

### Sequence

Premises: $\langle c_1,\sigma\rangle\Downarrow\rho$, $\langle c_2,\rho\rangle\Downarrow\tau$.

$$
\begin{aligned}
\langle c_1;c_2,\sigma\rangle
&\to^*\langle\mathsf{skip};c_2,\rho\rangle\\
&\to\langle c_2,\rho\rangle
\to^*\langle\mathsf{skip},\tau\rangle.
\end{aligned}
$$

Second command starts in updated state $\rho$.

### While-True

Let $W=\mathsf{while}\ b\ \mathsf{do}\ c$; abbreviate conditional syntax as $\mathsf{If}(b,c_1,c_2)$.

Premises: guard true in $\sigma$; body takes $\sigma$ to $\rho$; remaining loop takes $\rho$ to $\tau$.

$$
\begin{aligned}
\langle W,\sigma\rangle
&\to\langle\mathsf{If}(b,c;W,\mathsf{skip}),\sigma\rangle\\
&\to^*\langle\mathsf{If}(\mathsf{true},c;W,\mathsf{skip}),\sigma\rangle\\
&\to\langle c;W,\sigma\rangle\\
&\to^*\langle\mathsf{skip};W,\rho\rangle\\
&\to\langle W,\rho\rangle
\to^*\langle\mathsf{skip},\tau\rangle.
\end{aligned}
$$

Guard: Boolean lemma. Body and remaining loop: command IHs.

| Other case | Small-step construction |
| --- | --- |
| Skip | Zero steps |
| If | Evaluate guard; select branch; run branch |
| While-False | Unroll; evaluate guard; select skip |

## Reverse: small-step run → big-step

### Inversion

Read a derivation backward: its conclusion determines possible last rules and required premises.

Inversion is justified by inspecting the entire rule set. For example, only Assign can conclude a big-step judgment for an assignment, so any such proof must contain its arithmetic premise. A loop can end with either while rule, so inversion must keep both possibilities until the guard result distinguishes them.

| Known result | Recovered information |
| --- | --- |
| $\langle\mathsf{skip},\sigma\rangle\Downarrow\tau$ | $\tau=\sigma$ |
| $\langle x:=a,\sigma\rangle\Downarrow\tau$ | Some $n$: $\langle a,\sigma\rangle\Downarrow_a n$, $\tau=\sigma[x\mapsto n]$ |
| $\langle c_1;c_2,\sigma\rangle\Downarrow\tau$ | Some $\rho$: $\langle c_1,\sigma\rangle\Downarrow\rho$, $\langle c_2,\rho\rangle\Downarrow\tau$ |

### Anti-reduction

Reconstruct a big-step result **before** one small step:

$$
\frac{
\langle c,\sigma\rangle\to\langle c',\sigma'\rangle
\qquad\langle c',\sigma'\rangle\Downarrow\tau
}{\langle c,\sigma\rangle\Downarrow\tau}.
$$

Proof: induction on one-step derivation; invert result; apply IH or expression lemma; rebuild big-step rule. Quantify over **all final states**: sequence cases need intermediate results.

Expression version, proved first:

$$
\langle a,\sigma\rangle\to_a a'
\land\langle a',\sigma\rangle\Downarrow_a n
\Longrightarrow\langle a,\sigma\rangle\Downarrow_a n.
$$

Boolean version analogous.

**Assignment-Step case:**

1. Invert result for `x := a'`: obtain value $n$ and $\tau=\sigma[x\mapsto n]$.
2. Arithmetic anti-reduction: $a$ also evaluates to $n$.
3. Reapply Assign: `x := a` evaluates to $\tau$.

**Seq-Step case:** invert $\langle c_1';c_2,\sigma'\rangle\Downarrow\tau$ to obtain an intermediate state $\rho$. The IH for $c_1$'s step restores $\langle c_1,\sigma\rangle\Downarrow\rho$; keep $\langle c_2,\rho\rangle\Downarrow\tau$ and rebuild Seq. The IH needs result $\rho$, not merely the overall result $\tau$.

**While-unrolling case:** invert the big-step result of the unrolled conditional. False guard gives skip's unchanged state; rebuild While-False. True guard gives a sequence result; invert it into body and remaining-loop results, then rebuild While-True.

Anti-reduction preserves the final outcome across a known forward step. It does not claim that execution steps can be run backward.

### Finish by induction on the finite run

| Run case | Big-step proof |
| --- | --- |
| Zero steps to $\langle\mathsf{skip},\tau\rangle$ | Source already skip in state $\tau$; apply Skip |
| First step, then remaining run | IH gives result after first step; anti-reduction restores result before it |

Reverse expression proofs: same pattern, ending at a numeral or Boolean value.

For a run $C_0\to C_1\to\cdots\to C_k=\langle\mathsf{skip},\tau\rangle$, start with Skip's big-step result at $C_k$. Anti-reduction carries that result back across each known step, eventually reaching $C_0$. This explains how the induction reconstructs a proof without reversing the program's execution.
