# Lecture 7: IMP and Operational Semantics

**Main idea:** small-step semantics tracks the remaining program and current state after each step. Big-step rules: [Lecture 8](8.md); equivalence proof: [Lecture 9](9.md).

## IMP syntax

IMP isolates the basic features of imperative programming: variables hold integers, assignments change them, and commands control execution order. Unlike lambda-calculus substitution, an assignment changes a stored value without replacing every later occurrence of the variable in the program text.

Integer literals $n\in\mathbb Z$; variable names $x\in\mathrm{Var}$.

$$
\begin{aligned}
\mathrm{AExp}:\quad a&::=n\mid x\mid a_1+a_2\mid a_1-a_2\mid a_1*a_2,\\
\mathrm{BExp}:\quad b&::=\mathsf{true}\mid\mathsf{false}
 \mid a_1=a_2\mid a_1\le a_2\\
 &\quad\mid\neg b\mid b_1\land b_2\mid b_1\lor b_2,\\
\mathrm{Com}:\quad c&::=\mathsf{skip}\mid x:=a\mid c_1;c_2\\
 &\quad\mid\mathsf{if}\ b\ \mathsf{then}\ c_1\ \mathsf{else}\ c_2\\
 &\quad\mid\mathsf{while}\ b\ \mathsf{do}\ c.
\end{aligned}
$$

| Category | Purpose | Terminal form |
| --- | --- | --- |
| Arithmetic expression | Compute an integer | Numeral $n$ |
| Boolean expression | Compute a truth value | $\mathsf{true}$ or $\mathsf{false}$ |
| Command | Change the state | $\mathsf{skip}$ |

- $=$ tests equality; $:=$ assigns.
- Assignments are commands, not expressions: `x := (y := 1)` invalid.
- Terminal forms have **no small steps**, including no self-step.

## States and configurations

**State:** total map $\sigma\in\Sigma=(\mathrm{Var}\to\mathbb Z)$.

- Every variable has a supplied value; no automatic zero initialization.
- Mathematical integers: no overflow.
- Expressions read state; only commands modify it.

Think of $\sigma$ as a dictionary of current values. The program variable $x$ is syntax; $\sigma(x)$ is the integer stored for it. Different states can give the same expression different results.

**Update:** change one variable, preserve all others.

$$
\sigma[x\mapsto n](y)=
\begin{cases}
n & y=x,\\
\sigma(y) & y\ne x.
\end{cases}
$$

The update notation denotes a new mathematical map. For example, if $\sigma(x)=2$ and $\sigma(y)=5$, then $\sigma[x\mapsto3]$ maps $x$ to $3$ and still maps $y$ to $5$. Keeping the old and new maps separate makes each state change explicit in a proof.

**Configuration:** $\langle\text{remaining phrase},\text{current state}\rangle$.

| Relation | One-step result |
| --- | --- |
| $\langle a,\sigma\rangle\to_a a'$ | Remaining arithmetic expression; same state |
| $\langle b,\sigma\rangle\to_b b'$ | Remaining Boolean expression; same state |
| $\langle c,\sigma\rangle\to\langle c',\sigma'\rangle$ | Remaining command and possibly changed state |

Subscripts $a,b$ distinguish the expression relations from command stepping. Primes mark results after a step, not derivatives. Expression targets omit $\sigma$ because it stays unchanged.

## Arithmetic rules

Variable lookup:

$$
\frac{}{\langle x,\sigma\rangle\to_a\sigma(x)}.
$$

For $\odot\in\{+,-,*\}$: **left operand → right operand → compute**.

$$
\frac{\langle a_1,\sigma\rangle\to_a a_1'}
{\langle a_1\odot a_2,\sigma\rangle\to_a a_1'\odot a_2}
\quad(\text{A-Left})
$$

$$
\frac{\langle a_2,\sigma\rangle\to_a a_2'}
{\langle n_1\odot a_2,\sigma\rangle\to_a n_1\odot a_2'}
\quad(\text{A-Right})
$$

$$
\frac{}{\langle n_1\odot n_2,\sigma\rangle\to_a n_3}
\quad(\text{A-Compute}),
\qquad n_3=n_1\odot n_2\text{ in }\mathbb Z.
$$

These are rule schemas: choosing $+$, $-$, or $*$ gives a separate instance. The expression $2+3$ is still program syntax; $5$ is its computed numeral. The side condition uses ordinary mathematics to specify which numeral the computation rule returns.

Example with $\sigma(x)=2$, omitting the unchanged state:

$$
(x+1)*2\to_a(2+1)*2\to_a3*2\to_a6.
$$

First arrow: A-Var changes $x$ to $2$; A-Left lifts that change through the addition, then through the multiplication. Three rule applications justify **one** whole-expression step. Context rules move the computation's result outward without doing extra arithmetic.

## Boolean rules

$q,q_1,q_2\in\{\mathsf{true},\mathsf{false}\}$. Completion of the slides' exercise: **strict, left-to-right** $\land,\lor$; both operands evaluated.

### Comparisons

For $\bowtie\in\{=,\le\}$:

$$
\frac{\langle a_1,\sigma\rangle\to_a a_1'}
{\langle a_1\bowtie a_2,\sigma\rangle\to_b a_1'\bowtie a_2}
\quad(\text{Compare-Left})
$$

$$
\frac{\langle a_2,\sigma\rangle\to_a a_2'}
{\langle n_1\bowtie a_2,\sigma\rangle\to_b n_1\bowtie a_2'}
\quad(\text{Compare-Right})
$$

$$
\frac{}{\langle n_1\bowtie n_2,\sigma\rangle\to_b q}
\quad(\text{Compare}).
$$

$q$ true exactly when the integer comparison holds; false otherwise.

### Negation and binary operations

$$
\frac{\langle b,\sigma\rangle\to_b b'}
{\langle\neg b,\sigma\rangle\to_b\neg b'},
\qquad
\frac{}{\langle\neg q,\sigma\rangle\to_b\operatorname{not}(q)}.
$$

Here $\operatorname{not}$ flips the Boolean value. For $\diamond\in\{\land,\lor\}$:

$$
\frac{\langle b_1,\sigma\rangle\to_b b_1'}
{\langle b_1\diamond b_2,\sigma\rangle\to_b b_1'\diamond b_2}
\quad(\text{B-Left})
$$

$$
\frac{\langle b_2,\sigma\rangle\to_b b_2'}
{\langle q_1\diamond b_2,\sigma\rangle\to_b q_1\diamond b_2'}
\quad(\text{B-Right})
$$

$$
\frac{}{\langle q_1\diamond q_2,\sigma\rangle\to_b q}
\quad(\text{B-Compute}).
$$

$q$ from the truth table:

| $q_1$ | $q_2$ | $q_1\land q_2$ | $q_1\lor q_2$ |
| --- | --- | --- | --- |
| true | true | true | true |
| true | false | false | true |
| false | true | false | true |
| false | false | false | false |

**Alternative:** short-circuit rules skip the second operand when possible. Replace the strict rules; do not simply add competing rules. Same final values in this pure, terminating expression language; different traces.

For example, strict evaluation of $\mathsf{false}\land(x=0)$ still looks up $x$ and computes the comparison. Short-circuit evaluation can return false immediately. The truth table specifies the answer; the operational rules also specify the work performed to obtain it.

## Command rules

### Assignment: evaluate, then update

$$
\frac{\langle a,\sigma\rangle\to_a a'}
{\langle x:=a,\sigma\rangle\to\langle x:=a',\sigma\rangle}
\quad(\text{Assign-Step})
$$

$$
\frac{}{\langle x:=n,\sigma\rangle
\to\langle\mathsf{skip},\sigma[x\mapsto n]\rangle}
\quad(\text{Assign})
$$

For `x := x + 1`: read old `x`; update only after evaluating the right-hand side.

### Sequence: finish the first command

$$
\frac{\langle c_1,\sigma\rangle\to\langle c_1',\sigma'\rangle}
{\langle c_1;c_2,\sigma\rangle\to\langle c_1';c_2,\sigma'\rangle}
\quad(\text{Seq-Step})
$$

$$
\frac{}{\langle\mathsf{skip};c_2,\sigma\rangle\to\langle c_2,\sigma\rangle}
\quad(\text{Seq-Skip})
$$

Second command uses the state produced by the first.

The residual command records what still needs to run. After an assignment finishes, it becomes skip; Seq-Skip then removes that completed part and exposes the next command. A skip inside a sequence therefore differs from a whole configuration whose command is already skip.

### Conditional and loop

Compact notation for the ordinary IMP syntax:

$$
\begin{aligned}
\mathsf{If}(b,c_1,c_2)&\equiv\mathsf{if}\ b\ \mathsf{then}\ c_1\ \mathsf{else}\ c_2,\\
\mathsf{While}(b,c)&\equiv\mathsf{while}\ b\ \mathsf{do}\ c.
\end{aligned}
$$

$$
\frac{\langle b,\sigma\rangle\to_b b'}
{\langle\mathsf{If}(b,c_1,c_2),\sigma\rangle
\to\langle\mathsf{If}(b',c_1,c_2),\sigma\rangle}
\quad(\text{If-Step})
$$

$$
\frac{}{\langle\mathsf{If}(\mathsf{true},c_1,c_2),\sigma\rangle
\to\langle c_1,\sigma\rangle}
\quad(\text{If-True})
$$

$$
\frac{}{\langle\mathsf{If}(\mathsf{false},c_1,c_2),\sigma\rangle
\to\langle c_2,\sigma\rangle}
\quad(\text{If-False})
$$

Unroll once; write $W=\mathsf{While}(b,c)$:

$$
\frac{}{\langle W,\sigma\rangle
\to\langle\mathsf{If}(b,c;W,\mathsf{skip}),\sigma\rangle}
\quad(\text{While})
$$

- Only the selected branch executes.
- Unrolling leaves state unchanged.
- $W$ keeps the **original guard expression** $b$: reevaluate it after the body changes state.

Example: `while x <= 1 do x := x + 1`, starting at $x=1$. First test true; body sets $x=2$; next test false. Reusing the first test's value would incorrectly loop forever.

## Multiple steps and termination

For configurations $C,C',C''$:

$$
\frac{}{C\to^*C}\quad(\text{Refl}),
\qquad
\frac{C\to C'\qquad C'\to^*C''}{C\to^*C''}\quad(\text{Step}).
$$

- Zero or more steps; finite traces can concatenate.
- At each join: both command and state must match.
- Termination with result $\tau$: $\langle c,\sigma\rangle\to^*\langle\mathsf{skip},\tau\rangle$.
- $C\to^*C$ alone proves no loop: zero steps always allowed.

## Examples

### Two assignments

Distinct $x,y$; $\sigma_1=\sigma[x\mapsto1]$, $\sigma_2=\sigma_1[y\mapsto3]$.

$$
\begin{aligned}
\langle x:=1;\ y:=x+2,\sigma\rangle
&\to\langle\mathsf{skip};\ y:=x+2,\sigma_1\rangle\\
&\to\langle y:=x+2,\sigma_1\rangle\\
&\to\langle y:=1+2,\sigma_1\rangle\\
&\to\langle y:=3,\sigma_1\rangle\\
&\to\langle\mathsf{skip},\sigma_2\rangle.
\end{aligned}
$$

Rule sequence: Seq-Step around Assign; Seq-Skip; two Assign-Step uses; Assign. Only the first and last arrows perform state updates. The middle arrows simplify the remaining syntax.

### Euclid's subtraction algorithm

```text
while not (m = n) do
    if m <= n then n := n - m
    else m := m - n
```

For **positive** inputs:

$$
(m,n):\quad(6,4)\mapsto(2,4)\mapsto(2,2).
$$

Each arrow here = one complete loop iteration, not one small step. GCD preserved; $m+n$ decreases until equality; final common value = GCD. Zero inputs can loop.

Subtracting the smaller positive number preserves common divisors: a number divides both $m,n$ exactly when it divides both $m-n,n$. This proves preservation of the GCD. The separate decreasing quantity $m+n$ proves termination; preserving the answer alone would not rule out looping.

### Divergence

Let $W=\mathsf{While}(\mathsf{true},\mathsf{skip})$:

$$
\begin{aligned}
\langle W,\sigma\rangle
&\to\langle\mathsf{If}(\mathsf{true},\mathsf{skip};W,\mathsf{skip}),\sigma\rangle\\
&\to\langle\mathsf{skip};W,\sigma\rangle
\to\langle W,\sigma\rangle.
\end{aligned}
$$

Positive-length cycle: three actual steps, repeat forever. Rules deterministic; expressions always terminate, commands may diverge.
