# Lecture 3: Reductions, NP-Completeness, and Cook–Levin

**Main point:** known hard problem → new problem; starting point = SAT via Cook–Levin

## NP versus coNP

**Setup:** polynomial-length $u$; polynomial-time predicates

$$
\begin{aligned}
\text{NP form:}\quad x\in L&\iff\exists u\;V(x,u)=1,\\
\text{coNP form:}\quad x\in L&\iff\forall u\;W(x,u)=1.
\end{aligned}
$$

**coNP form:** negation of an NP verifier for $\overline L$

The symbol $\forall$ means “for every.” Negating “there exists a certificate accepted by $V$” gives “every certificate is rejected by $V$,” so take $W=1-V$.

For UNSAT, the universal check asks whether **every assignment fails**. One failed assignment cannot prove unsatisfiability; one satisfying assignment can disprove it.

- **Known:** $\mathrm P\subseteq\mathrm{NP}\cap\mathrm{coNP}$
- **Open:** P = NP? NP = coNP? P = NP $\cap$ coNP?
- P = NP → all three equal
- NP = coNP → P = NP: unknown

## Polynomial-time many-one (Karp) reductions

$$
\boxed{A\leq_p B\iff
\exists\text{ polynomial-time }f:\ x\in A\iff f(x)\in B.}
$$

- **Every input $x$:** one instance → one instance; yes/no answers preserved
- Algorithm for $A$: compute $f(x)$ → run solver for $B$

- $A\leq_p B$, $B\in\mathrm P$ → $A\in\mathrm P$; likewise for NP
- Composition: $A\leq_p B\leq_p C$ → $A\leq_p C$
- **Hardness direction:** known hard $A$ → target $B$

**Why this direction:** an efficient solver for $B$ would solve $A$ through the reduction. Since writing $f(x)$ costs time, its length is also polynomially bounded.

**Example: Clique → Independent Set**

**Clique:** vertex set with an edge between every pair of distinct vertices

Complement edges between distinct vertices:

$$
\langle G,k\rangle\mapsto\langle\overline G,k\rangle.
$$

**Correctness:** clique in $G$ ⇔ independent set in $\overline G$

## NP-hard and NP-complete

| Term | Requirement |
| --- | --- |
| **NP-hard** | $A\leq_p B$ for every $A\in\mathrm{NP}$ |
| **NP-complete** | NP-hard **and** $B\in\mathrm{NP}$ |

**Proof checklist:** efficient verifier + hardness reduction; NP-hardness alone insufficient for NP membership

An NP-complete problem can express every NP problem through an efficient translation. Solving it efficiently would therefore solve every NP problem efficiently.

**Consequence:** any NP-complete problem in P → P = NP

## Bounded machine acceptance: TMSAT

**Deterministic verifier $M$:**

$$
\begin{aligned}
\mathrm{TMSAT}=\{\langle M,x,1^m,1^t\rangle:
&\exists u\in\{0,1\}^m,\\
&M(x,u)\text{ accepts within }t\text{ steps}\}.
\end{aligned}
$$

- **In NP:** guess $u$ → simulate $t$ steps; unary bounds → polynomial time in input length
- **NP-hard:** verifier $V$, witness bound $p$, time bound $q$ → reduction

$$
x\mapsto\langle V,x,1^{p(|x|)},1^{q(|x|)}\rangle.
$$

**Result:** TMSAT NP-complete

TMSAT receives the verifier's code as part of its input. For a reduction from one particular NP language, that verifier $V$ is fixed; only $x$ and the resource bounds vary.

**Why unary:** $1^t$ occupies $t$ input symbols. A binary bound would occupy only $O(\log t)$ bits, so simulating $t$ steps could be exponential in input length.

## SAT notation

- **Literal:** $z$ or $\neg z$
- **Clause:** an OR of literals
- **CNF:** an AND of clauses, $\varphi=\bigwedge_i\bigvee_j\ell_{ij}$
- **SAT:** satisfiable CNF formulas
- **k-SAT:** satisfiable CNF formulas with at most $k$ literals per clause

**Certificate:** satisfying assignment; polynomial-time evaluation

**Example:** $(a\lor\neg b)\land b$ requires both clauses true. Choosing $a=b=1$ satisfies it.

## Cook–Levin: SAT is NP-complete

**Goal:** NP verifier $V$ → polynomial-size CNF $\varphi_x$

$$
\boxed{\varphi_x\text{ satisfiable}\iff\exists u\;V(x,u)=1\iff x\in L.}
$$

### Construction: describe an accepting computation

- Runtime bound: $T=\operatorname{poly}(|x|)$, including one-tape simulation
- **Tableau:** $T+1$ configuration rows × $O(T)$ tape positions

Each row is a snapshot of the entire machine at one time. A satisfying assignment chooses the snapshots, while the constraints force them to form one legal accepting computation.

**Cell alphabet:** tape symbols, with head/state attached at the scanned cell

$$
t_{i,j,\sigma}=1\iff\text{cell }j\text{ at time }i\text{ contains }\sigma.
$$

**Four CNF constraint groups:**

| Constraint | What it enforces |
| --- | --- |
| **Cell** | Exactly one symbol per cell |
| **Start** | Fixed state, head, input $x$, blanks; free certificate bits |
| **Move** | Legal transition between consecutive rows |
| **Accept** | Accepting final row; accepting states persistent until $T$ |

**Exactly one:** at least one symbol + pairwise exclusions

$$
\left(\bigvee_\sigma t_{i,j,\sigma}\right)
\land\bigwedge_{\sigma\neq\tau}
(\neg t_{i,j,\sigma}\lor\neg t_{i,j,\tau}).
$$

**Locality:** one step changes only scanned cell/state/head. Forbidden constant-size neighborhoods + boundary rules + valid first row → legal computation

To forbid a local pattern, add a clause saying that at least one of its entries must differ. The fixed transition rules give only constantly many such patterns per location, keeping the whole formula polynomial-size.

### Correctness and size

- **Accepting witness → satisfying assignment:** actual computation tableau
- **Satisfying assignment → accepting witness:** first-row certificate + legal moves + accepting final row
- **Size:** fixed alphabet; $O(T^2)$ cells; polynomial clauses and construction time

**Variables:** certificate bits + auxiliary tableau variables

**Key idea:** the reduction writes constraints without knowing an accepting witness. A satisfying assignment supplies the missing witness and its computation; no accepting computation means no satisfying tableau.
