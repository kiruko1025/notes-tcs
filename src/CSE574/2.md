# Lecture 2: Computation, P, and NP

**Main point:** P = efficiently solvable; NP = efficiently verifiable

Here “efficient” means polynomial in input length. A Turing machine models an algorithm using tape memory, a read/write head, and finitely many states.

## Computation and complexity

- **Church–Turing thesis:** effective computability = Turing-machine computability
- **Extended thesis:** simulation of reasonable models with polynomial overhead; physical versions dependent on classical/randomized/quantum model
- **Complexity:** required time, space, randomness, communication, etc
- **Upper bound:** resource usage of an algorithm
- **Lower bound:** minimum resources required by every algorithm

**Caution:** slow algorithm ≠ hardness proof

Computability asks whether any algorithm can solve a problem; complexity asks how many resources a solution needs. One fast algorithm proves an upper bound, but a lower bound must rule out every faster algorithm.

## Languages and input size

**Language:** set of yes instances

$$
L\subseteq\{0,1\}^*,\qquad
x\in L\iff\text{the answer on }x\text{ is yes}.
$$

- **Decider:** correct answer + termination on every input
- $n=|x|$: encoding length
- $\langle G,k\rangle$: encoding of structured data

For example, the primality language contains binary encodings of prime integers. Encoding a question as a string lets us discuss numbers, graphs, and formulas within the same model.

**Input-size trap:** binary $N$ → $\Theta(\log N)$ bits; $O(N)$ time → generally exponential in input length

**Example:** an $n$-bit integer can be almost $2^n$. Trying every smaller integer can therefore require exponentially many steps, despite a short input.

## P and NP

| Class | Meaning |
| --- | --- |
| $\mathrm{DTIME}(T(n))$ | Deterministic decision in $O(T(n))$ time |
| $\mathrm{NTIME}(T(n))$ | Nondeterministic decision in $O(T(n))$ time on **every branch** |

$$
\boxed{\mathrm P=\bigcup_{c\geq1}\mathrm{DTIME}(n^c),
\qquad\mathrm{NP}=\bigcup_{c\geq1}\mathrm{NTIME}(n^c).}
$$

The union allows each language its own fixed exponent $c$. One polynomial bound suffices; the exponent cannot grow with the input.

- **Accept:** at least one accepting branch
- **Reject:** all branches rejecting
- **Nondeterminism ≠ randomness**

Think of the computation as a tree of possible choices. NP bounds the length of each branch; a deterministic search through all branches could still take exponential time. Acceptance depends on existence, not the probability of choosing a successful branch.

### NP as verification

**NP characterization:** polynomial-time verifier $V$, polynomial witness bound $p$

$$
\boxed{x\in L\iff\exists u\in\{0,1\}^{p(|x|)}\;V(x,u)=1.}
$$

- $u$: **witness/certificate**
- Yes instance: some valid witness
- No instance: no valid witness

**Reading the formula:** $\exists u$ means “at least one certificate”; $V(x,u)=1$ means “the check accepts.” The verifier receives $u$—it does not need to find it.

- **Machine → verifier:** witness = accepting branch choices
- **Verifier → machine:** guess witness → verify

- Shorter witnesses: padding to fixed length
- NP = **nondeterministic polynomial time**, not “non-polynomial”
- Deterministic computation: no choices needed → $\mathrm P\subseteq\mathrm{NP}$

## Examples

| Problem | Question or certificate | Membership |
| --- | --- | --- |
| Primality | Primality of binary integer $N$ | P |
| Connectivity | All vertices reachable by BFS/DFS | P |
| Linear programming | Real feasibility of $Az\leq b$; rational $A,b$ | P |
| Independent Set | At least $k$ pairwise nonadjacent vertices | NP |
| Decision-TSP | Tour through each city once; cost at most $B$ | NP |
| Graph Isomorphism | Vertex bijection preserving edges/nonedges | NP |
| Bounded factoring | Divisor $d\mid N$; $2\leq d<N$, $d\leq k$ | NP |

- All listed NP certificates: polynomial-time checks
- Prime factor in $[a,b]$: divisibility + primality + interval checks

**Independent Set example:** path $1-2-3$, threshold $k=2$. Certificate $\{1,3\}$: two vertices, no edge between them. Verification only checks the supplied set; finding it is a separate task.

**Independent Set:** existence of size $k$ ⇔ existence of size at least $k$; different from **maximum** size exactly $k$

## coNP

**Complement:** $\overline L=\{0,1\}^*\setminus L$

$$
\mathrm{coNP}=\{L:\overline L\in\mathrm{NP}\},\qquad
\operatorname{coNTIME}(T)=\{L:\overline L\in\mathrm{NTIME}(T)\}.
$$

- NP: short certificates for **yes**
- coNP: short certificates for **no**
- P: closed under complement by swapping accept/reject

For a coNP language $L$, a certificate proves that an input is **outside** $L$. The prefix “co” means complement; it does not mean “outside NP.” A language may belong to both NP and coNP.

$$
\boxed{\mathrm P\subseteq\mathrm{NP}\cap\mathrm{coNP}.}
$$
